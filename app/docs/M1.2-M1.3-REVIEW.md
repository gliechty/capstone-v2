# M1.2 + M1.3 — Assessment interaction review

Implemented for human review; this does not mark either step complete.
The owner's combined authorization includes M1.3 despite its PENDING roadmap label.
M1.4 and Milestone 2 remain unstarted.

## Scope and choices

- /assessment is a dedicated page reached by the existing landing CTA.
- The existing warm surfaces, Manrope font, rust accent and category tokens remain.
- One scoped React reducer/context owns setup, method, position, raw answers, skips,
  review and the non-production terminal state.
- Browser sessionStorage is accessed only by src/adapters/assessment-session.ts.
  The adapter has an injectable storage port, versioned key and validated snapshot.
  Storage access happens after mount; no empty initial state is written before restore.
- The previously approved Zod choice is now installed, pinned to 4.6.5, for the
  persisted input boundary. No alternate state management or component framework.
- Setup collects company name, industry, subindustry, company size, location,
  target market, target buyer and business goal. Subindustry is optional; other
  fields are required. Company size is a positive whole employee count.
- Industry/subindustry and commercial context are free text for the UI preview.
  They do not load canonical config, imply approved option lists or select questions.
  "Not yet identified" can represent an unknown buyer.
- Manual input is the only active method. Calculator/upload choices are disabled
  with visible explanations.
- Six separately versioned demonstration fixtures cover boolean, categorical, text,
  numeric and percent interactions across People, Governance, Community and Resources.
  They do not import QuestionBank or represent approved methodology.
- Click/tap on categorical or boolean options advances after 280ms. Keyboard arrows
  and Space select without advancing; Enter or Continue confirms. Pending timers
  cancel on keyboard input, another pointer action, or leaving the question.
  Text/numeric/percent inputs retain explicit Continue.
- Raw drafts save on change, not blur. Navigation and Skip retain existing values.
  Clear answer is explicit. Empty/invalid values are unanswered; zero is a valid
  numeric answer. UI numeric validation is not scoring normalization.
- The compact category-grouped progress rail expands on desktop hover/focus.
  Mobile uses a tap disclosure. Both expose direct navigation, state symbols,
  current rings and inspected-question context; the marker region scrolls at a
  bounded height. Tests exercise 50 presentation items without expanding fixtures.
- Adjacent questions are selectable partial cards with a directional opacity
  gradient, 0.96 scale, and 220ms forward/backward vertical translation.
  Reduced motion removes animation.
- The landing header is sticky; its measured height offsets anchor scrolling
  as navigation wraps or fonts resize.
- Review reports missing/invalid answers and allows direct editing or jumping to
  the first missing answer. Generate score anyway opens only the clearly labeled
  no-score boundary on /assessment. No /results route or submission exists.

## Persistence and limitations

Snapshots carry both storage version and mock-fixture version. Unknown versions,
malformed JSON, excessive size, unknown IDs, invalid shapes and invalid profiles
in non-setup stages are rejected. A fresh state opens with a visible explanation.
Blocked reads and failed writes are handled without crashing the flow; write failure
warns that refreshing/leaving may lose recent changes. Draft text remains in memory.

This is tab-session retention, not durable accounts, cross-device sync or server
storage. Browser restore/duplicate-tab behavior is browser-dependent. The UI asks
for example data and explains retention. No data is sent to a server by this flow.
Canonical field mappings, validated production questionnaire configuration and
scoring policy belong to later authorized work.

## Verification coverage

Unit tests cover required setup fields, numeric/percent validation, reducer
navigation, skip/revisit, progress derivation, missing review, state round trips,
incompatible/corrupt snapshots and unavailable/quota-limited storage.

Production browser tests cover landing entry; validation and focus; disabled
methods; refresh of partial setup, input-method and questionnaire states; raw draft
retention; zero versus missing; invalid percent; direct progress jumps; category
changes; review/no-score boundary; keyboard controls; reduced motion; desktop and
mobile axe scans; overflow; screenshots; absence of /results.

Golden scoring tests are not applicable to these mock-only UI capabilities.
The deterministic-domain boundary and its tests remain unchanged.
No Build Pack or roadmap status edits are part of this work package.

## Deferred minor UX follow-ups

Both items are non-blocking follow-ups for Milestone 1 final polish / real-question integration:

- **Assessment → Home navigation:** Returning home currently restores/focuses near the bottom of the landing page rather than reliably returning to the top.
- **Progress navigator selection affordance:** Expanded question-text items need a clearer hover/focus affordance so users understand that both the text items and track markers are selectable.
