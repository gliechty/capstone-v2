## Mock and architecture boundaries

src/content/results-preview.ts is an explicitly named, isolated presentation fixture.
Its values are independently chosen layout examples, not calculated aggregates or
historical Golden results. It is never a fallback on a scoring/provider failure.
The results route is a server-rendered presentation shell. It reads no session data,
accepts no score parameters and calls no APIs, providers, retrieval or domain engine.
No new dependency, database, report generator or state-management system was added.
The assessment reducer, storage adapter, validation and deterministic domain boundary
remain unchanged. The assessment still stops with no score generated; opening the
mock results requires an explicitly labeled link. Missing answers remain missing.
The page can safely render with no session or a malformed session because it makes
no claim to represent that session. Session error handling still occurs in assessment.

When authorized later, validated deterministic outputs and separately validated
recommendation/evidence outputs can replace this presentation fixture through the
existing architecture. No production result contract or scoring policy is invented here.

## M1.4 navigation refinement

A sticky desktop section navigator links to Summary (scores first), Key Gaps,
Recommended Actions and Evidence/Sources without changing their order. Mobile uses
an explicit native disclosure with the same links, closing on selection or Escape.
Native anchors move focus to the target section; scroll offsets keep targets clear
of the sticky navigator. Reduced-motion preferences retain instant anchor scrolling.
The navigator is a small client island; results and mock fixtures remain independent
of session state. No dependencies or new architecture patterns were introduced.

Muted-paper summary/source surfaces, raised gap cards and restrained line variations
reinforce section boundaries. Numbered navigation and action rows aid scanning;
no generic ESG icon set or decorative animation was added.
