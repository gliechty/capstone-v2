# M2.3–M2.5 review

Status: implemented and verified on 2026-10-10; awaiting human acceptance. Milestone 2 is not complete. M2.6 and M2.7 remain unauthorized.

## Implemented scope

- Framework-independent deterministic scoring in src/domain/scoring/score-assessment.ts. Existing selected canonical questions and persisted raw answers feed normalization, benchmark resolution, base weights, contextual multipliers, category aggregation and overall scores.
- POST /api/assessment-score validates bounded JSON, canonical setup options, config/session version and answer IDs; it reselects questions and recomputes using trusted repository config. No client score/config is accepted. No answers are logged or saved on the server. Company name, subindustry and other unnecessary context are not submitted.
- Results reuse the existing visual shell and display computed overall/category values. Missing categories say “Not scored”; empty assessments have no numeric score. Invalid nonblank drafts fail visibly and must be corrected or cleared. No mock-score fallback exists.
- Executive Summary, Key Gaps, Recommended Actions and evidence remain explicitly fictional examples. Reports remain disabled. No provider calls, database or new dependency.

## Preserved behavior and precision

Authority: published AssessmentScoring in the preserved Appsmith export, canonical migrated config, and all five Golden cases. Selection remains unchanged.

AnswerScale matching trims and case-folds options. Benchmarks prefer matching industry, then global/all/none/blank fallback, then the first active metric row in source order, exactly as the preserved scorer. Numeric methods are the ten methods represented by canonical config. Optional blank parameters retain the source Number("") = 0 interpretation; zero required denominators and malformed/non-finite values fail explicitly.

Multiplier matching uses tags, category, subcategory, industry, target-market region, buyer and goal. The preserved region/buyer/goal comparison is case-folded substring matching, not a new token OR interpretation. All matched rules multiply before the explicit 1.5 final cap from AssessmentScoring.getMultiplier. Location does not become a new multiplier dimension.

Missing answers have no normalized/earned/possible values. Category and raw denominators include answered questions only, as in v1. Missing category percentages and contributions remain null; the weighted sum uses observed categories without redistributing canonical weights. An entirely unanswered assessment returns null overall scores, replacing the legacy empty-assessment zero. Invalid answers stop calculation instead of being silently dropped by legacy aggregation.

Numeric implementation uses JavaScript binary64, converting preserved decimal strings at the calculation boundary. No intermediate decimal rounding is applied; the UI alone formats one decimal. This follows the explicitly authorized precision requirement. Canonical category weights retain their full precision. Internal diagnostics retain raw answer, benchmark/scale record, method, base weight, matched rule records, product/cap, earned/possible and category contributions with configuration/method identity. This is supporting work for this package, not completion of M2.6.

## Golden comparison and known capture limitations

The tests first replay the untouched preserved scorer and compare its captured question-level normalization, method, base weights, matched rules, weighted/final/possible values and category aggregates against all five immutable Golden fixtures. Manufacturing category totals were captured at whole-point precision. Benchmark record identity is checked against preserved resolution code because the question-level fixtures do not capture full benchmark records.

A separate isolated test-only replay removes decimal formatting from the preserved scorer, then compares the new full-precision engine. The comparison allowance is 32 scaled machine epsilons solely for floating-point operation order; it does not absorb decimal rounding or category-weight differences. Dedicated formula and failure-path tests supplement the source replay.
