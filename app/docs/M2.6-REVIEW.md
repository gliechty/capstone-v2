# M2.6 review — calculation trace and explainability

Status: implemented and verified on 2026-10-11; awaiting human review. M2.7 remains PENDING and unauthorized. Milestone 2 is not complete.

## Changed

- The deterministic engine emits a typed, versioned per-question calculation trace from the same intermediates used for scoring. Raw inputs and derived values remain separate. Missing rows contain no fabricated score.
- The score API exposes the trace and input snapshot in the scored-assessment JSON. Benchmark identity, source records, normalization operands, multiplier IDs/product/cap and category/overall contributions support audit and mechanical legacy comparisons.
- Results add a collapsed-by-default “How this score was calculated” disclosure, per-question explanations, optional exact technical JSON and the full scored-assessment JSON. No UI scoring formulas, report generation or authentication requirement.
- Results invalidate/recompute on relevant session changes and page restoration. Abort and generation guards reject stale responses; failed browser saves cannot authorize older saved inputs in the same page lifetime.
- NUMERIC-POLICY.md records source precision, binary64 representation, intermediate/presentation rounding, comparison tolerances and historical Golden limitations.

## Decisions and boundaries

The scoring method version is unchanged: this is observability for the accepted method, not a formula change. Trace schema version 1 is independent of method/config identity. No dependency or architecture replacement. Raw browser session storage remains the persisted authority; the API/visible JSON carries the calculated record and is recomputed rather than cached. No company name is sent to scoring.

Existing fictional narrative, recommendations and source placeholders remain clearly labeled. M2.7, report generation, recommendation computation, database persistence and commercial concepts are not implemented. Existing deferred UX items remain deferred. BUILD_PACK is immutable.
